# 聚合客服系统原型

> 版本：v0.1  
> 日期：2026-10-14  
> 状态：静态视觉原型  

---

## 一、这版原型要验证什么？

这一轮不做完整功能，只验证三件事：

1. **统一工作台**能不能把管理、开发、坐席三种视角合并到一套界面里。
2. **客服聊天室**是不是产品中心，而不是被后台配置功能淹没。
3. **Flutter App** 是否能复用同一套颜色和组件语言，覆盖移动端客服值守和简单管理。

---

| 原型 | 文件 | 说明 |

## 三、PC 统一工作台界面

PC 端原则：

1. 只有一个 Web 工作台，不再拆管理后台、开发者后台、坐席后台。
2. 左侧导航保持简单，避免配置功能比客服工作更重要。
3. 权限决定菜单可见性，不决定界面结构。
4. 聊天室是一级入口。

界面包括：

```text
工作台
├── 总览
├── 会话
├── 聊天室
├── 业务渠道
├── 转发渠道
├── AI 客服
├── Webhook
├── 消息日志
└── 设置
```

不同角色看到的内容：

| 角色 | 重点 |
| --- | --- |
| 管理员 | 服务健康、租户配置、渠道状态、失败告警。 |
| 开发者 | App 注册、AccessToken、转发渠道、Webhook、消息日志。 |
| 坐席 | 会话认领、聊天室、客户信息、人工接管、AI 建议回复。 |

---

## 四、Flutter App 界面

Flutter 端不追求把 PC 后台完整搬过来。

移动端优先做：

```text
登录 / 选择工作区
├── 客服值守
│   ├── 会话列表
│   ├── 聊天室
│   ├── 客户详情
│   └── 人工接管
├── 服务状态
│   ├── 在线 App
│   ├── 转发渠道状态
│   └── 失败消息
└── 我的
    ├── 角色与权限
    ├── 消息通知
    └── 外观设置
```

移动端原则：

1. 聊天列表和聊天室是最高优先级。
2. 管理功能只保留健康检查和紧急处理，不做复杂配置。
3. Android、iOS、Flutter Web 使用同一套布局规则。
4. 不做桌面客户端，桌面访问统一走 PC Web。
